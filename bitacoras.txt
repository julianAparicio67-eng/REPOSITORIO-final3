P0 (Momento 0)
Cliente: Quien hace la petición (el navegador, Postman o una aplicación).
Servidor: Quien recibe la petición, procesa los datos y devuelve una respuesta.
Entrada (Request): Viaja el método HTTP ( GET, POST), la URL, los encabezados y 
opcionalmente un cuerpo con datos.
Salida (Response): Viaja el código de estado ( 200, 404, etc.), los encabezados y 
el cuerpo de la respuesta (texto, JSON o HTML).

4.2 Filtrar: req.query

Predicción P8 — escríbela en tu bitácora ANTES de ejecutar
Predice el resultado de estas tres peticiones: ?tipo=agua, ?tipo=AGUA y ?tipo=fuego. 
Para la última: ¿debería responder 404 o 200 con una lista vacía? Defiende tu respuesta.

RTA:
?tipo=agua: Devuelve un código 200 con la lista de las actividades de agua (como
rafting y torrentismo).

?tipo=AGUA: Devuelve un código 200 pero con una lista vacía ( []) , porque JavaScript es 
estricto con las mayúsculas y minúsculas ("AGUA" no es igual a "agua").

?tipo=fuego: Devuelve un código 200 con una lista vacía ( []) .

¿Debería ser 404 o lista vacía? 
Debe responder 200 con una lista vacía , porque la ruta /actividadessí existe y la búsqueda
es válida. Que no haya resultados para "fuego" no es un error del sistema, simplemente 
significa que la tienda no tiene actividades de ese tipo por ahora.

Momento 6 · Cerrar las puertas: el 404 propio

Predicción P11 — escríbela en tu bitácora ANTES de ejecutar
Mueve este bloque al inicio, justo después de express.json(), y pide GET /actividades. 
¿Qué pasa? ¿Por qué? Después regrésalo al final.

RTA:Lo que sucede es que aparece esto en la consola:
{
    "mensaje": "No existe la ruta GET /actividades"
}
Pasa esto porque Express ejecuta todo estrictamente en orden de aparición . Las rutas
específicas van arriba y el recolector de errores (el 404) va siempre al final.


Conclusión para la bitácora
Escribe en una frase cómo decide Express qué código ejecutar cuando llega una petición.

RTA: la conclucion es que Express procesa las peticiones siguiendo un estricto orden 
secuencial de arriba hacia abajo, evaluando cada ruta o middleware hasta que uno responde 
o llama a next para continuar con el siguiente.
